# Kromic Store Backend Implementation Guide

# Phase 02 -- 10 Base Entities and Auditing

**Version:** 1.0\
**Status:** Approved Foundation

------------------------------------------------------------------------

# Purpose

This document defines the common entity model shared across the entire
Kromic Store backend.

Every entity should inherit from the appropriate base class instead of
duplicating common properties.

------------------------------------------------------------------------

# Design Goals

-   Eliminate duplicated properties
-   Consistent auditing
-   Consistent soft delete behavior
-   Tenant-aware entities
-   EF Core friendly
-   Future-proof inheritance

------------------------------------------------------------------------

# BaseEntity

Responsibilities:

-   Primary Key
-   Domain event support (optional)
-   Equality by Id

Required members:

-   Id (Guid)

Rules:

-   Every persisted entity inherits BaseEntity.
-   IDs are generated by the application.

------------------------------------------------------------------------

# AuditableEntity

Adds audit information.

Fields:

-   CreatedOnUtc
-   CreatedBy
-   ModifiedOnUtc
-   ModifiedBy

Rules:

-   Created fields populated once.
-   Modified fields updated on every change.

Audit values should be populated automatically by infrastructure.

------------------------------------------------------------------------

# TenantEntity

Represents entities owned by a tenant.

Adds:

-   TenantId

Examples:

-   Product
-   Category
-   Customer
-   Address
-   Theme
-   Order
-   Cart
-   Wishlist

Rules:

-   TenantId is immutable after creation.
-   Never accept TenantId from client payloads.

------------------------------------------------------------------------

# Soft Delete Model

Every business entity supports soft delete.

Fields:

-   IsDeleted
-   DeletedOnUtc
-   DeletedBy

Behavior:

-   Queries exclude deleted rows by default.
-   Restore operations clear deletion metadata.
-   Physical deletion is reserved for archival or maintenance.

------------------------------------------------------------------------

# Concurrency

Use optimistic concurrency.

Recommendation:

-   PostgreSQL xmin system column or
-   EF Core concurrency token

Never overwrite concurrent updates silently.

------------------------------------------------------------------------

# Shared Interfaces

Recommended interfaces:

-   IAuditable
-   ISoftDeletable
-   ITenantEntity

Interfaces should describe capabilities rather than implementation.

------------------------------------------------------------------------

# Domain Events

Optional support:

-   Entities may raise domain events.
-   Events are dispatched after successful transaction commit.
-   Use the Outbox pattern for external integrations.

------------------------------------------------------------------------

# EF Core Configuration

Apply common configuration centrally.

Examples:

-   Global query filters
-   UTC conversion
-   Concurrency configuration
-   Soft delete filters

Avoid repeating identical Fluent API across entities.

------------------------------------------------------------------------

# Audit Population

Audit fields should be set automatically during SaveChanges.

Values come from:

-   Current user
-   Current tenant
-   System account for background workers

Never trust values supplied by API clients.

------------------------------------------------------------------------

# Background Workers

When no authenticated user exists:

CreatedBy / ModifiedBy:

System

This should be represented consistently across all workers.

------------------------------------------------------------------------

# Business Rules

-   Every tenant-owned entity inherits TenantEntity.
-   Every business entity inherits AuditableEntity.
-   Never duplicate audit properties.
-   Never bypass audit logic.

------------------------------------------------------------------------

# Testing Requirements

Verify:

-   Audit fields populate correctly.
-   TenantId is assigned automatically.
-   Soft delete hides records.
-   Restore behaves correctly.
-   Concurrency conflicts are detected.

------------------------------------------------------------------------
