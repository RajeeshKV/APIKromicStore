# Kromic Store Backend Documentation

# Phase 06 -- 124 Entity Framework Core Standards

**Version:** 1.0\
**Status:** Approved Foundation

------------------------------------------------------------------------

# Purpose

This document defines Entity Framework Core (EF Core) standards for
Kromic Store to ensure consistent data access, maintainable mappings,
high performance, and predictable behavior across all services.

------------------------------------------------------------------------

# Objectives

-   Standardize EF Core usage
-   Improve maintainability
-   Optimize database access
-   Prevent common ORM pitfalls
-   Support multi-tenant architecture
-   Simplify testing and migrations

------------------------------------------------------------------------

# DbContext Design

Guidelines:

-   One DbContext per bounded context
-   Keep DbContext lightweight
-   Register using dependency injection
-   Configure through extension methods
-   Avoid business logic in DbContext

------------------------------------------------------------------------

# Entity Configuration

Configure entities using IEntityTypeConfiguration`<T>`{=html}.

Recommendations:

-   One configuration class per entity
-   Keep configuration separate from entities
-   Centralize model registration

Avoid data annotations for complex mappings.

------------------------------------------------------------------------

# Fluent API

Use Fluent API for:

-   Keys
-   Relationships
-   Constraints
-   Indexes
-   Precision
-   Default values
-   Concurrency tokens

Prefer Fluent API over attributes for consistency.

------------------------------------------------------------------------

# Value Converters

Use value converters for:

-   Enums
-   Value Objects
-   Strongly typed IDs
-   Custom value types

Keep conversions deterministic and reversible.

------------------------------------------------------------------------

# Query Optimization

Recommendations:

-   Project only required columns
-   Use pagination
-   Avoid N+1 queries
-   Use Include selectively
-   Prefer compiled queries for hot paths
-   Review generated SQL

------------------------------------------------------------------------

# Tracking Behavior

Use:

-   AsNoTracking() for read-only queries
-   Tracking only when updates are required

Reduce unnecessary change tracking overhead.

------------------------------------------------------------------------

# Transactions

-   Use explicit transactions for multi-step operations
-   Keep transactions short
-   Integrate with the Outbox Pattern where required

------------------------------------------------------------------------

# Concurrency

Use optimistic concurrency with row version/concurrency tokens.

Handle conflicts by:

-   Retrying
-   Refreshing entities
-   Returning meaningful errors

------------------------------------------------------------------------

# Migrations

Guidelines:

-   One logical change per migration
-   Review generated SQL
-   Test on staging
-   Keep migrations source-controlled

------------------------------------------------------------------------

# Performance

Monitor:

-   Query execution time
-   Slow queries
-   Connection pool usage
-   Tracking overhead
-   Database round trips

------------------------------------------------------------------------

# Testing

Verify:

-   Entity mappings
-   Relationships
-   Value converters
-   Concurrency
-   Migrations
-   Query performance

------------------------------------------------------------------------

# Best Practices

-   Keep DbContext focused.
-   Use Fluent API consistently.
-   Prefer AsNoTracking for reads.
-   Optimize queries before scaling.
-   Review SQL generated by EF Core.
